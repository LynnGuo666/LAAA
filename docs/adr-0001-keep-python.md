# ADR-0001: 后端保持 Python/FastAPI，暂不迁移到 Go

- **状态**：已接受（Accepted）
- **日期**：2026-10-22
- **决策者**：LAAA 维护者
- **相关**：设备信任记忆（`known_devices`）、部署形态（1c1g VPS + Docker）

## 背景

LAAA 后端是 FastAPI + SQLAlchemy + SQLite，前端是 Next.js 静态导出（运行时无 Node）。
部署目标是单核 1GB 的 VPS（1c1g），通过 GitHub Actions 构建镜像、服务器只 `pull + run`。

曾评估“把后端迭代成 Go 以降低资源占用”。本 ADR 记录实测数据与结论，避免后续重复讨论。

## 实测数据

在 macOS 上以临时数据库启动真实实例（含启动时预载 GeoIP），测量后立即清理：

| 指标 | 实测值 |
|---|---|
| 后端常驻内存 RSS（uvicorn 单 worker，GeoIP 已载入） | **≈108 MiB**（111,104 KB） |
| 仅 import 基线（不加载 GeoIP） | ≈89 MiB（93,765,632 B） |
| GeoIP 预载增量 | 约 14–17 MiB |
| 前端静态产物 | 2.9 MB |
| 后端代码 | 12,451 行 / 96 个路由 |
| 测试代码 | 5,515 行 |
| 数据库 | SQLite，458 KB / 25 张业务表 |

1c1g 上的预算：

| 项目 | 占用（估算） |
|---|---|
| 系统 + systemd + sshd | 100–150 MB |
| Docker daemon + containerd | 80–120 MB |
| LAAA 后端 | ≈108 MiB |
| **常驻合计** | **约 300–380 MB / 1024 MB（30–37%）** |

## 决策

**保持现有 Python/FastAPI 技术栈，不迁移到 Go。**

理由：

1. 1c1g 上仍有约 600–700MB 余量，Go 能省的 65–80MB（约 7%）没有实际收益。
2. 真实瓶颈与语言无关：
   - 登录延迟由 bcrypt cost 12 决定（≈250ms/次），Go 使用相同 cost 不会更快；
   - 并发上限由 SQLite 单写锁决定，换语言不改变；
   - 这是个人级身份服务，QPS 极低。
3. 迁移成本高、风险集中：
   - 96 个端点，涉及 OAuth2/OIDC、PKCE、refresh token 家族重放检测、
     WebAuthn/Passkey、TOTP 时间步防重放、风控 step-up、RBAC、邀请码、
     邮件验证、Magic Link、限流、静态托管、Alembic 迁移；
   - 保守估计全职 4–8 周，且安全语义回归难以通过“跑通”发现；
   - 现有 5.5k 行回归测试是主要安全网，重写期间需要额外维护两套。
4. 当前部署形态已接近 1c1g 最优：
   - 镜像由 CI 构建（Node 构建发生在 GitHub Runner，不占 VPS 内存）；
   - 生产 `CMD` 为单 worker、无 `--reload`、`--proxy-headers`；
   - GeoIP 为 mmap，页面缓存可回收。

## 迁移触发条件（重新评估的门槛）

只有满足以下任一条件，才重新启动 Go 迁移评估：

1. 目标环境内存 ≤128MB，或需要单二进制分发（无 Python/无容器运行时）。
2. 出现持续 >50 QPS 的并发需求，或需要 CPU 密集型的自定义计算。
3. 维护者本人希望用 Go 长期维护该项目，并接受 4–8 周迁移与回归风险。
4. Python 生态无法满足的硬性依赖出现（例如特定平台只允许静态二进制）。

## 后果

**正面**

- 不承担重写风险，安全修复与功能迭代继续在当前代码库进行。
- 保留现有测试、迁移脚本、部署流水线。

**负面**

- 内存占用比 Go 高约 65–80MB；镜像体积大约多 200–300MB。
- 需要继续维护 Python 依赖与运行时。

## 1c1g 上的替代优化（按收益排序）

1. **不要在服务器上执行 `--build`**：Next 构建的 Node 峰值可达 500MB–1GB，
   这是 1c1g 唯一现实的 OOM 场景。生产只用 `docker-compose.prod.yml pull`。
2. **限制容器日志**：`json-file` + `max-size: 10m` / `max-file: 3`，防止小盘被打满。
3. **加 1–2GB swap**：低成本兜底构建/异常峰值。
4. **可选 `mem_limit: 320m`**：防止异常泄漏拖死整机。
5. **定时备份 `oauth.db`**：比换语言重要得多。
